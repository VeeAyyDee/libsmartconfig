FORMAT
Lengths are UDP payload lengths (capture removes constant wire overhead).
CRC8 initial0, reflected0x8c, no finalxor (existing sc_touch_crc8).
The header sequence starts:1048,1071+N,1048,1071+N, then8 data-plane packets.
N includes the header itself. Each body sequence j (0-based) begins with
128+j repeated3 times, then8 data-plane packets. Our decoder need only one
marker to select j; repeats before planes are harmless. N bounds1..41.
A data-plane packet is64|(i<<7)|d, where i0..7, d0..63. Thus marker bit6=1,
length64..1023. Decode six bytes B[0..5] by taking bit(5-k) of d_i as bit i
of B[k]. Distinguish body markers128..167 (bit6=0), sync1048, count1072..1112.
Packets outside these supported sets reset only partial framing, not collected
validated sequences. Each8-plane group must have all indices0..7. Repeated
same plane harmless, conflicting plane values discard current partial group
(not entire session); next marker resynchronizes. Sequence marker switch clears
partial planes, but consecutive same markers BEFORE data do not.

Header is six full8-bit bytes H0..5. H0: SSID len low7bits, highbit means8-bit
encoding. H1: password len low7, highbit encode. H2: reserved len low7, highbit
encode. H3: CRC8(target6-byteBSSID). H4: bit0IPv4 flag (0IPv6), bits1..2
security version0/1/2; bits3..4 reply port mark0..3; bit5reserved0; bits6..7
protocol version0. H5 CRC8(H0..4). Bounds SSID0..32,password0..64,reserved0..64.
Reject protocol!=0, reserved bit5, security3 or impossible sizes. A byte-codec
emptySSID is allowed but not claimed provisionable. Header is always full8-bit.

Body group encodings (not to be confused with AES security):
- 7-bit group carries six bytes with all high bits0. Planes0..6 carry bit0..6
  of all six. Plane7 low6bits is CRC8(the six bytes)&63, NOT their bit7 plane.
- 8-bit group carries five arbitrary bytes plus full CRC8(those five bytes)
  in byte B5; all eight planes encode these six full bytes.
Random padding bytes fill each logical segment to a multiple of its group
width (6 or5). Padding participates in per-group CRC; excluded from result.

Layout after header:
security0 with password-encode=0 AND reserved-encode=0: concatenate password
and reserved into ONE7-bit segment, padded to multiple6. Then SSID segment.
security0 otherwise: password segment with width5 if encodebit else6; separately
reserved segment similarly; then SSID segment. Empty segment uses no groups.
SSID segment always width5 if H0highbit else6, padded accordingly.
security1/2: concatenate plaintextpassword||reserved, AES128-CBC encrypt with
PKCS#7 padding to next16-byte boundary (always at least1 padding byte).
Ciphertext length C=16*(floor((P+R)/16)+1). Transmit ciphertext as width5 groups
(with random group-padding to multiple5). No separate reserved segment.
security1 IV is16zero bytes. security2 inserts20 transmitted random IV bytes
as four width5 groups between ciphertext andSSID; only first16 used as CBCIV,
last4 are transported/checksummed but not cryptographic IV bytes.
AES cipher's plaintext PKCS#7 must validate exactly: decrypted C bytes, expected
plaintext length P+R, pad length C-(P+R) in1..16, EVERY pad byte equals padlength.
Encrypted mode without decrypt callback/key stays unsupported/incomplete and
must not expose credentials. Decryption failure or invalid padding must not
expose partial output. Never claim CRC/padding authenticates sender or key.
Sender actually chooses security0 if key supplied but P+R=0; don't generate
security1/2 with zero P+R in own encoder tests except deliberate invalid input.
Require computed group count+header==N, and all expected validated sequences.
Seq CRC has no index binding; source/session separation is caller policy.
Receive header before body; body before accepted header may be ignored. Permit
reordered groups after header, identical repeats and repeated same header.
Any CRC-valid changed header or CRC-valid changed committed sequence before
completion poisons session until reset. Count changes after established header
also poison if count is in bounds. Invalid CRC/framing never commits bytes.
Frozen completion until reset. Output only after full validation and decryption.
