Important architecture: SDK6.0.3 esp_wifi ALREADY builds open-source wrapper
esp_smartconfig_start/stop and SC_EVENT definition. It owns automatic ACK task
through its event handler and sc_send_ack_start/stop. Retain that wrapper;
do NOT duplicate those public symbols or ACK machinery. Implement exported
esp_smartconfig_internal_start(const smartconfig_start_config_t*) and
esp_smartconfig_internal_stop(void) called by wrapper, plus public
esp_smartconfig_get_version, esp_esptouch_set_timeout, esp_smartconfig_set_type,
esp_smartconfig_fast_mode, esp_smartconfig_get_rvd_data from public header.
SDK wrapper registers an SC_EVENT_GOT_SSID_PSWD handler before internal_start,
unregisters it on start failure; successful stop stops ACK and unregisters it.
Publish standard events via existing SC_EVENT (extern), standard struct fields,
actual protocol type and token/cellphone_ip required by SDK ACK sender. Core
must not auto-connect: application consumes credentials and connects as usual.

Use autonomous owned task/timer driving capture, not caller polling. Serialize
lifecycle; bounded resources. Event handlers may call stop. Never block joining
self, deadlock on event delivery, destroy worker-owned state still in use, or
leave installed promiscuous callback after buffers freed. Stop must cleanly
support start/stop/start and partial startup rollback. Credentials event only
once/session, FOUND_CHANNEL before GOT_CREDENTIALS. SCAN_DONE only after real
scan completion if you implement scanning; don't fabricate a completed scan.
No credential logging even when enable_log true (operational logs okay).
Validate started WiFi station or APSTA; APSTA must preserve running AP channel.
Normal disconnected STA hopping remains. Don't silently offer APSTA by retuning
an active AP; lock its channel or return explicit unsupported if cannot support.
Reject conflicting existing promiscuous owner; document exclusivity.

Types0 ESPTouch,1 AirKiss,2 simultaneous ESPTouch+AirKiss,3 ESPTouchV2.
Default type2. Combined mode needs ONE capture/radio owner feeding both decoders,
selecting first valid protocol and retaining channel once a candidate locks;
existing protocol adapters separately installing callbacks is not sufficient.
Prefer common compatible receiver integrating own portable capture decoders.
Public APIs shouldn't silently claim combined mode/fast-mode unsupported parts

Use v2 crypt flag/key16; NULL key when encrypted=>ARG; copy key before returning.
Public API has no AirKiss key argument: default standard AirKiss remains plaintext;
keep existing explicit keyed AirKiss optional extension available, don't conflate
v2 key flag with AirKiss encryption. Preserve encrypted AirKiss core/tests.

Reserved-data getter copies v2 reserved bytes with requested length/bounds,
validate NULL and availability; no uninitialized bytes. See own v2 result struct.
